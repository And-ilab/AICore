## 2. Запуск и вход в систему

### 2.1. Доступ

1. Открыть URL контура (_TBD: prod URL Заказчика_; локальный ориентир — см. [backend README](../../backend/README.md): frontend `:5173`, backend `:8000`).
2. Выполнить вход через корпоративную учётную запись (LDAPS / AD).
3. Убедиться, что в портале доступны разрешённые модули (RBAC I.4).

_TBD: скриншот экрана входа Заказчика._

### 2.2. Портальный лаунчер AI Hub

1. Нажать кнопку **AI Hub** (правый нижний угол).
2. Выбрать **Суфлёр** и/или **Ассистент** — окна независимы.
3. Свернуть / закрыть / изменить размер окна по необходимости.

При отсутствии прав лаунчер и маршруты модулей недоступны.

## 3. Модуль Контакт-центра — суфлёр (телефония)

**ТЗ:** II.3 · приёмка SUF-T.

### 3.1. Типовой сценарий

1. Принять вызов в Oktell (_TBD: рабочее место оператора Заказчика_).
2. Открыть суфлёр (лаунчер / вкладка Hub при активном звонке).
3. Дождаться распознанной реплики клиента (ASR).
4. Просмотреть карточки подсказок: текст, % релевантности, ссылка на статью СУЗ.
5. При необходимости развернуть карточку; перейти по ссылке СУЗ в новой вкладке.
6. Оставить обратную связь по подсказке (_TBD: точные подписи кнопок по макету_).

**Важно:** текст подсказки клиенту **не** передаётся автоматически (I.2.3).

### 3.2. Ограничения

| Ситуация | Действие пользователя |
|----------|------------------------|
| Нет подсказок / низкая релевантность | Продолжить диалог по скрипту банка; сообщить супервизору |
| ASR недоступен | _TBD регламент_ |
| Ссылка СУЗ не открывается | Проверить VPN/доступ; эскалация ДИТ |

## 4. Онлайн-чат и суфлёр в АРМ

**ТЗ:** II.4–II.5 · приёмка CHAT-T.

### 4.1. Типовой сценарий оператора

1. Открыть АРМ онлайн-чата.
2. Выбрать диалог из очереди; при необходимости сменить статус оператора (онлайн / обед / …).
3. Читать сообщения клиента; использовать панель суфлёра (подсказки, вставка в ответ).
4. Отправить ответ клиенту **вручную** (автоотправка подсказки запрещена по умолчанию).
5. Завершить диалог, указать категорию (_TBD поля Заказчика_).

## 9. Действия в аварийных ситуациях

| Ситуация | Действия пользователя | Эскалация |
|----------|----------------------|-----------|
| Нет входа в систему | Проверить AD/пароль, VPN; не использовать чужие УЗ | Служба поддержки / ДИТ |
| Модуль не открывается / 403 | Сообщить администратору (права RBAC) | Админ Hub |
| Подсказки не появляются при звонке | Проверить индикатор ASR/сессии; продолжить без суфлёра | Супервизор + дежурный ИТ |
| Долгий ответ LLM / таймаут | Повторить запрос один раз; зафиксировать время | Админ / мониторинг |
| Подозрение на утечку ПДн в ответе | **Не** копировать клиенту; сообщить ИБ | ИБ Заказчика |
| Полный отказ контура | Работать по бумажным/штатным процедурам банка | _TBD регламент ОПЭ_ |

## 10. Рекомендации и ограничения

- Не передавать клиенту сырой текст подсказки без проверки.
- Не вводить в формы реальные ПДн на TEST без согласования ИБ.
- Обратная связь по подсказкам обязательна там, где требует ТЗ (SUF-T / CHAT-T).
